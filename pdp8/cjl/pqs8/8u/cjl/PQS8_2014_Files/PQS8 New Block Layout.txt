The above is subject to change; how to generate a system is undergoing modification; to
create a system now will require the presence of the corresponding non-system handler
to be used to write out components to the proper blocks.  As such, there will no longer
be any kludges to force the system device handler from an image into a callable routine
during system generation.  Non-system device handlers perform their own internal
page and field relocation and thus are always callable.  Establishan appropriate
portion of memory for the handler assuming perhaps more memory first.  Once the process
has been refined, consider something such as reserved for non-system handler no larger
than some x pages, and then an extra field for handlers that are too large.  As a
practical manner, most non-system device handlers should be four pages or less is a
reasonable starting point; if that amount can fit, then it defines how to avoid the
need for yet another field.  How much the base sysgen requirement may change as a
result of other changes indicated later in this document.
