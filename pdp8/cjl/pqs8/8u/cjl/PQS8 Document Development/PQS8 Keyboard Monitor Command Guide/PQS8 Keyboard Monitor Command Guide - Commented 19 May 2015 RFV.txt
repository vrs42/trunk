This document is a guide to the P?S/8 keyboard monitor and integrated line editor.
All available commands are documented sufficiently for beginning users to get
started using P?S/8 for common text editing, initiating program execution and
related tasks.

Conventions used in this document.

All commands are given in upper-case characters; as an accommodation, lower-case
characters are "folded" to their upper-case equivalent as typed.  As such, the
commands are shown in upper-case characters.  With the exception of the R command,
all commands require the first two characters as shown; additional characters are
allowed and will be ignored.  Commands will be shown with certain optional trailing
characters enclosed in brackets indicating the usual meaning of the command for
clarification purposes only.

Commands that access files by name.

Certain commands allow optional arguments that are file names taken from the
standard P?S/8 directory structure known as the Tiny File System [TFS].  In general,
file-oriented commands can also reference the special positional multiple purpose
files known as % and $ [which are located near the physical start of every system
device unit for faster access].  Where this usage applies, the command will be
followed by "filnam".  [Note: The actual TFS file names are upper-case only.]

Logical device unit access.

Many commands indicate an optional :u suffix.  The current logical unit in effect
can be updated using an appended :0 through :7 corresponding to the desired logical
device unit.  [Note: Logical units are processed by the operating system in a
hardware-dependent manner.  For example, when P?S/8 is implemented on the
TC01/TC08/TU55/TU56 DECtape storage device, the logical units refer to the physical
DECtape drive tape units which can be changed using drive-mounted unit-select
switches.  On the TD8E/TU56 DECtape, only the low-order bit of the logical unit is
meaningful; as such, all even logical units refer to drive 0 and all odd logical
units refer to drive 1.  On the RX01 or compatible diskette device, the
configuration may be analogous to the TD8e as cited above; however, certain RX
storage systems support up to four drives; in these larger configurations, only the
high-order bit of the logical unit is ignored; references to drive 3 would be the
same as drive 7, etc.  The current configuration is established dynamically at
bootup time by the system device handler; there are several implementations of
RX-compatible systems on various machines such as the VT78, DECmate I, DECmate II
RX278 option, DSD-210 and DSD-440 on various computers manufactured by DEC and
third-party providers.]  [Note:  Future implementations of the P?S/8 system device
handler for the TD8E without the MR8E-C ROM may extend support to as many as four
TD8E controllers; this would allow up to four dual-drive TU56 transports in a
suitably configured system; within each dual-drive pair, it will be necessary to
select the appropriate unit switch position as each dual drive can only address two
specific tape drive units.  Systems that use the MR8E-C ROM cannot be extended due
to internal limitations of the ROM coding.]

In general, commands that allow the optional :u suffix and optional file name
arguments will allow the :u suffix on the passed file name.  [Note: Only commands
for program execution allow multiple file names to be specified; the optional :u
suffix is allowed on the program name and every specified input or output file name
as required.]  All commands and file name options will indicate the optional :u
suffix where appropriate.

Where appropriate, the commands of the integrated line editor operate on text
specified by line number.  This refers to the contents of the tentative file buffer
only.  Until the tentative buffer is saved to a permanent file, it is only available
in memory while the keyboard monitor is active.  If a file is loaded into the
tentative buffer, changes can be made in a variety of ways; the modifications are
not applied to the storage device until the tentative buffer is written to a
permanent file.  Note: While line numbers are permanently assigned, various commands
are available to change the permanent setting within the tentative file buffer;
writing to a permanent file updates all file contents including the permanent line
numbers.

Command parameters expressed as a range of line numbers.

Certain commands take an optional range of line numbers [indicated in the command
description as line-number-range] that determine the scope of the command operation:

1) nnnn		The stated line nnnn is selected; if this line does not exist, no
		operation occurs.

		One such command is the LI[st] command, which outputs the line
		number and contents of specified lines to the system console
		terminal.  For example, LIST 1000 will output line 1000 [if line
		1000 exists].

2) ssss-	The operating range for the command is line ssss through the end of
		the file.  Line ssss does not need to exist and only serves as a
		limiting value.  If no lines exist within this range, no operation
		occurs.

		For example, LIST 500- will output lines 500 and higher through the
		end of the file.

3) -ffff	The operating range for the command is the beginning of the file
		through line ffff.  Line ffff does not need to exist and only serves
		as a limiting value.  If no lines exist within this range, no
		operation occurs.

		For example, LIST -2000 will output all lines in the file through
		line 2000.

4) ssss-ffff	The operating range for the command is lines ssss through ffff.
		Lines ssss and ffff need not exist and only serve as limiting
		values.  If no lines exist within this range, no operation occurs.

		For example, LIST 300-700 will output all lines that fall in the
		range of 300 through 700.

5) <none>	If the line-number-range is omitted, the operating range for the
		command is all lines within the file.  If the file is empty, no
		operation occurs.

		For example, LIST will output all lines in the file.

Commands parameters expressed as a starting line number and line number increment.

*** Shouldn't "Commands parameters" be "Command parameters"? ***

Certain commands take an optional line number parameter [and perhaps an optional
line number increment].  This is indicated in the command description as
optional-starting-line-number and optional-line-increment.  If neither parameter is
present, the default starting line number is 100.  The default line increment is 10
and can only be changed if the starting line number parameter is present.

For example, the RE[sequence] command will reorder the line numbers in a file.  The
command RESEQUENCE [without parameters] will reorder the line numbers starting at
100 and all subsequent lines are incremented by 10.  RESEQUENCE 1000 50 will reorder
the line numbers starting at 1000 and all subsequent lines are incremented by 50.
RESEQUENCE 2000 will reorder the line numbers starting at 2000 and all subsequent
lines are incremented by 10.

Some commands use other unique forms of parameter passing; this will be explicitly
documented within each command description as appropriate.

In the interest of overall brevity, certain command descriptions may reference other
commands with expanded description elsewhere; this will always be obvious due to the
format of all commands as described above; it may be necessary to first reference
the description of other command[s] to better understand the current command
description.  [This is unavoidable as many of the commands are inter-related.]

History of the P?S/8 command processor and fundamental design issues.

P?S/8 is a direct outgrowth of the predecessor operating system known as the
R-L Monitor System [named for the principal authors' initials] or MS/8 [as it was
submitted to DECUS].  This more primitive system uses the basic concept of commands
with only the first two characters significant, allowing additional optional
characters that are ignored.  [Note: While the R-L Monitor System allows six
character file names, system program names are limited to two characters; additional
program name characters are ignored.]

The R-L Monitor System was cosmetically modified [the names of certain commands were
changed using trivial binary patches while retaining the command functionality] as a
stopgap measure incorporated into the early release of DIBOL-8.  This temporary
official DEC product, which is similar at the command level to future releases of
systems supporting the DIBOL-8 compiler, had only the modest goals of supporting the
earliest DIBOL-8 compiler and the ability to load the binary output of compilation.
[Note: All of the systems described here use the exact same binary output format
internally, thus identical loading techniques apply; the BIN system utility program
exists throughout DIBOL-8, the R-L Monitor System and all releases of P?S/8 albeit
with slightly different command syntax due to the evolving nature of the command
execution process within each system.  P?S/8 adds many additional features and
operating modes to the BIN utility; when only file names are passed to BIN, the
functionality is identical to The R-L Monitor System and DIBOL-8; binary files from
these systems can be copied to P?S/8 using available commands and utilities.  The
R-L Monitor System implementation of BIN is limited to 4K memory support only; the
binary file format supports 32K memory as implemented only in P?S/8.]

The largest weakness of DIBOL-8 [which would be overcome in later releases which
became known as COS-300/310 or Commercial Operating System Version 3] was the
primitive nature of initiating program execution of the compiler and related utility
programs; the only information that can be passed to any system program are the
contents of user-specified input files [binary output is to an implied portion of
the TC01/TC08/TU55/TU56 DECtape, the only device supported in the original DIBOL-8]
and a 12-bit octal value expressed on the command-line as =xxxx where xxxx is any
4-digit octal number.  [Note: For backward compatibility, P?S/8 internally supports
the =xxxx parameter identically to the predecessor systems.]

*** What was the 12-bit octal number expressed as =xxxx for?  How was it (meant to be) used? ***

P?S/8 and COS-300/310 were developed independently but on a parallel track to
improve execution processing by implementing a compact form of what is known in
other DEC systems as Concise Command Language [CCL].  This includes the ability to
pass input and output files and option switches [while retaining the =xxxx value
which was repurposed in all instances other than specifying a starting address to
binary loading utilities].

P?S/8 initially retained consistency with the R-L Monitor System command set where
possible.  As a result, a conflict arose between some system program names and the
command names.  [Note: As described above, the R-L Monitor System only allows two
characters for system program names as well as command names.  Both P?S/8 and
COS-300/310 allow up to six character system program names where additional
characters [for program names that are exactly six characters] are ignored which is
analogous to the way command names are ignored beyond the first two characters in
all of these systems.]

*** Corrected spelling of "described" above. ***

The DIBOL-8 system command names were chosen to allow the execution of the compiler
and other projected system utilities by avoidance of anomaly between these program
names and command names [regarding the first two characters].  Execution can always
be initiated by appropriate execution commands (R or RU[n]) to resolve any conflict
that could arise; however, the goal was to avoid the need to routinely resort to
this for all common programs and system utilities [as well as eliminate certain
forms of overhead which is noticeable on tape-based systems].

*** Corrected spelling of "noticeable" above. ***

Eventually, a parallel design change was gradually made to P?S/8 over the course of
several releases.  For example, the R-L Monitor System provides a command useful
during BATCH operations:

.PAUSE TELL THE OPERATOR TO DO SOMETHING AND THEN PRESS ANY KEY TO CONTINUE

The BATCH process is paused; the entire command line is shown on the system console
[even if echoing of commands is otherwise suppressed]; execution continues after any
key is pressed on the system console.

As first implemented in DIBOL-8 [and retained in COS-300/310] the command name was
later changed in P?S/8 to:

.PLEASE DO SOMETHING AND THEN PRESS ANY KEY TO CONTINUE

The general reason for this change was to allow concise command execution of an
implementation of the PAL assembler [which is generally found in all of these
systems, although the specific assembler referenced may be a completely different
implementation of the PDP-8 Assembly Language processor].  By avoidance of a command
name expressed as PA, the assembly can be concisely initiated by the PAL program
name, thus avoiding the need to use R PAL [or perhaps RU[n] PAL] and the attendant
overhead.

Known surviving implementations of P?S/8 were created circa 1976 where the command
names were in transition [without direct contact with the DIBOL-8 or COS-300/310
development process].  As such, while the command names are somewhat different from
the R-L Monitor System, these releases are not identical to the eventual release of
P?S/8 circa 1989 [which is in the process of being made available as part of a
further process of additional modifications for new work, including the P?S/8 SHELL
overlay].

Abort character and related considerations.

*** Do you want to change to "Control-C" rather than "control-C"?  Or is the capitalized version too "modern"?  There's even a Wikipedia page on "Control-C."  Basically, do you want to capitalize the word "Control" when discussing these commands below? ***

In general, all of the operating systems described here support the control-C
character as a general abort and return to the keyboard monitor [by reboot if the
abort is detected within a conforming program that will exit to location 007600].
Within the keyboard monitor, control-C will generally abort an incomplete command
being typed [perhaps in auto-sequenced line number input mode]; however, the
original character to accomplish this was control-D as used in the R-L Monitor
System and early P?S/8 releases.  In newer releases, the keyboard monitor abort
character was changed to control-Z to be more consistent with other DEC operating
systems.

As first implemented in the R-L Monitor System, when the keyboard monitor is
accepting input [and subject to abort or terminal control characters], it is
possible to press control-R or control-T.  The disposition of these characters is
device-dependent.  On the TC01/TC08/TU55/TU56 DECtape system, control-R will rewind
the current logical unit allowing tape motion to overlap with further command
typing; the tape will stop in the reverse end zone automatically.  Pressing
control-T will rewind the tape, then the tape will be forced off the takeup reel.
If the selected drive is a type TU55, the brakes will be locked; the keyboard
monitor resumes control after the tape is fully unloaded.

1976 P?S/8 commands and footnotes.

CA[talog]:u

	Obtain a quick TFS directory listing on the console printer.  The output
	format is four file names per line.  Files are outputted according to the
	physical order in which they appear.  Empty entries will always be indicated
	unless physically last in the directory [and thus the first of an indefinite
	number of inactive directory slots].  [Note: Multiple EN[ter] and DE[lete]
	operations may cause a series of trailing empty entries depending on
	specific circumstances.  The CA[talog] command will print out deleted file
	entries as empty entries as only the very last entry [or the first entry
	never used] is truly empty by either having never been used, or cleared as a
	special-case handled by the DE[lete] command.  Thus, depending on
        circumstances, the directory may contain a series of trailing empty entries
        indicated in the printout.  [Note: This is a deliberate design decision to
        partially aid in file recovery; if it is clear there are no indicated empty
        entries, the latest DE[lete] operation clears the very last active entry,
        thus making it obvious that a restorative EN[ter] command will recover the
        affected file.  When there are multiple indicated empty slots, it is harder
        to determine the former associated name.  By always having all active
        entries containing unique names, it is possible to recover from the
        accidental deletion if quickly noticed [before another file is saved over
        the file slot]; however, not all users abide by this safe technique.

	[Arguments can be made regarding brevity of directory printout versus the
	ability to more easily recover from an accidental file deletion; users who
	opt for the all slots filled method will find it easier to recover; the
        other alternative depends on running utilities to observe the deleted file
        name which shows all of the rest of the file name characters; only the first
        character is deleted and converted to an internally impossible case.  This
	method has been copied by other systems such as MS-DOS for the same purpose
	of helping to undelete files, etc.]  [Note: The 1976 release of P?S/8
        does not include any utilities oriented around recovering from accidental
        deletion; the all slots filled method or equivalent is the only method
        available short of using the general-purpose P?S/8 DUMP utility which
        requires a level of proficiency not only of the DUMP program, but in the
        TFS structure itself.  Later releases include some efforts to solve this
        problem by means other than the DE[lete] and EN[ter] commands] available in
        all P?S/8 releases.]

	To minimally clean up the directory, the DE[lete] command checks to see if
	the deletion affects the very last active directory slot; if this is the
	case, the entry is cleared establishing the active end of the directory one
	slot closer to the beginning of the directory.  If other empty directory
	entries immediately precede this entry, they will not be automatically
	removed to possibly aid in file recovery in case of accidental deletion;
	however, these entries can be removed by entering as many transient file
	names [meaningful to the user] as is required, then using the DE[lete]
        command to remove the entries in strictly reverse order.  [As described,
        this is a deliberate design compromise between cosmetics and file recovery
        issues.]

	Note: Even with the file name destroyed, as long as the actual file contents
	has not been overwritten, the EN[ter] command can be used to attempt to read
	areas of the tape corresponding to the directory entries; the files can be
	loaded into the editor and inspected; there is no guarantee that anything
	coherent will be found as in many cases this is merely reading the former
	contents of the corresponding blocks.  This would be considered the last
        resort to recover from accidental deletion; attempting recovery by this
        method does not involve execution of any utility program.  [In the process
        of attempting file recovery by this method, the directory will be filled
        with new file entries chosen by the user; in essence, the method of last
        resort forces the user to use the recommended method of having all entries
        pre-filled with arbitrary names convenient to the user.]

EC[ho] [optional 0 or 1]

	Inverts the state of output of command characters if no argument given.
	EC[ho] 0 forces all output off; EC[ho] 1 forces all output on.  Pressing
	control-O during any output operation in progress overrides this by
	immediately reversing the echo state for each control-O pressed.  This
	command is generally used within BATCH control files to limit output to the
	system console.

EN[ter]:u filnam:u

	A specified [or default from a prior file name command] file name is entered
	into the directory; no actual file storage is modified.  This can be useful
	for recovering accidentally deleted files or preselecting multiple file
	names for later use to take advantage of relative file placement for maximum
	efficiency.

	On certain tape systems, some programs can access the contents of files
	faster if the files are arranged in an interleaved manner; the EN[ter]
	command can setup the proper file placement prior to any actual editing
	operations.

	For example, on TC01/TC08/TC55/TU56 systems, it is impossible to access
	adjacent files without causing a tape turnaround.  [Note: This is a hardware
	restriction.  If a DECtape handler allowed tape motion when the handler
	exits, the tape would always eventually wind into the forward end zone; the
	next tape operation would first have to rewind the tape to just below the
	desired initial tape block, then turn around to cause forward tape motion.
	Since every call to the system device handler stops the tape, the next call
	must be to an area slightly further up the tape and not immediately adjacent
	for a forward initial search to be effective.  In the specific case of TFS
	files, this means attempts to access the immediately adjacent file will
        cause a tape turnaround; accessing a file an additional file slot [or more]
	further up the tape will start with forward motion and the tape operation
        will successfully finish without a tape turnaround.

	Thus, by arranging the files of a project in an interleaved order, access to
	the files is greatly increased.  The interleave can be accomplished either
	by having files from an unrelated project interdigitated with the current
	project files, or the project files can be split into halves, with the
	second half files between the first half files; there would be no
	turnarounds in the former case and one turnaround in the latter case due to
	having to rewind to access the second half files.

	The "slurp" binary loader for TC01/TC08/TU55/TU56 always starts with an
	initial forward search to more quickly access the binary files, which are
	generally located further up the tape from the loader code image.  The
	interleaved file approach will increase file access for binary files as this
	improves the loading process as well; as such, it would be prudent to
        interleave binary output files with the source code files of the same

Appendix A.

P?S/8 keyboard monitor command names and related design considerations.

The P?S/8 keyboard monitor and integrated editor commands are stored internally in
block 0013 of the system device as a table of two word entries:

1) A 12-bit word containing the six-bit code for the command [inverted],

2) The 12-bit address of the command within the keyboard monitor and integrated
   editor as loaded into memory.

possible to modify the table to prevent certain commands if desired; all standard
systems allow all commands per se.  [Note: The ED[it] command is inhibited during
BATCH operations only.]  There is no defined order to the implemented commands; for
the most part, they are implemented in alphabetical order.
